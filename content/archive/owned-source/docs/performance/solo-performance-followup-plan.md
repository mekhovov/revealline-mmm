## Body-backing restoration finding and limits

A weak cache held a Canvas2D mask after restoration had cleared its pixels, leaving an opaque-interior character backing blank. The Coupa flower preset can reach this helper through character rendering in Solo. #1712 tracks lost/dirty surfaces, avoids replacement allocations during loss and rebuilds on the next paint after restoration. Event-supported clean hits avoid native polling, dimension reads and pixel readback; image ownership remains weak. It preserves alpha/pivot/geometry and the existing fill algorithm.

Canvas restoration does not retain prior content. The repair deliberately does not call `preventDefault()` on Canvas2D `contextlost`, because that suppresses automatic restoration. ## Research review and resulting decisions

- **Separate input-delay components before attributing touch failures.** Chrome distinguishes input delay, handler processing and presentation delay. Our elapsed boundary from `event.timeStamp` to a late observer listener can include queueing plus earlier handlers; it is not pure queue time. Inspect those components separately in diagnostics. Pointer Events permits browser delay/coalescing, but this possibility does not establish the cause of the retained failures or justify changing input APIs, synthetic input, thresholds or the existing Warm frame-trace scope. [Chrome interaction breakdown](https://developer.chrome.com/docs/performance/insights/inp-breakdown), [W3C coalesced events](https://www.w3.org/TR/pointerevents3/#coalesced-and-predicted-events).

- **Keep optional module loading within its existing owner.** The chooser has one use inside the guarded Missions request; moving its import there removes seven eager modules without a new loading system. The fresh-process refusal test establishes source-host isolation, not native network-retry behavior. Current HTML specifies removal of failed fetch entries, while evaluated modules have separate caching semantics; browser-version behavior still requires observation. Preserve explicit full-document boot recovery rather than adding unbounded query-string imports or alternate evaluation. [Module fetch algorithm](https://html.spec.whatwg.org/multipage/webappapis.html#fetch-a-single-module-script), [dynamic import caching](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import#module_namespace_object).
- **Review completed work before adding experiments.** The post-publication audit found selected-font correctness already observed, final production artifacts available, and the Cocoa identity successor already executed. Correct stale plan status before commissioning repetitions. The next hosted lanes reuse the verified package and existing workloads; source/tooling identities remain distinct.
- **Treat normal-clock precision as a limitation of the overhead claim.** The High Resolution Time specification permits implementation-defined coarsening and jitter. A measured minimum clock step is not a proven error bound. A tighter bounded offline interval method can reduce unnecessary slack under its stated assumptions, but cannot establish that assumption or turn old failed rows into a pass. [High Resolution Time coarsening](https://www.w3.org/TR/hr-time-3/#dfn-coarsen-time).
- **Keep diagnostic tracing out of ordinary timing.** Current Chrome documentation warns that advanced paint instrumentation and CSS-selector statistics significantly affect performance, and that CPU throttling cannot reproduce mobile CPU architecture. Use separate attribution runs and preserve the actual device requirement. [Performance recording settings](https://developer.chrome.com/docs/devtools/performance/overview), [throttling limitations](https://developer.chrome.com/docs/devtools/performance/reference#throttle-the-cpu-while-recording).
- **Budget decoded pixels, not only downloaded bytes.** A Safari 26 report reproduces memory termination with twenty parallel 4000 × 4000 image decodes. WebKit explains that explicit `decode()` uses natural dimensions without the display path’s subsampling. The existing actor pool reserves decoded RGBA bytes (64 MiB standard, 32 MiB compact), and the legacy painter serializes decoding with a 16-million-pixel retained limit. Preserve reservations through non-cancelable decode settlement and verify settled owners after transitions. This supports the existing policy; it does not establish this phone’s failure cause. [WebKit image-decoding example](https://bugs.webkit.org/show_bug.cgi?id=302801).
- **Inspect Safari canvases separately from timing.** Web Inspector can report canvas dimensions and memory and record drawing commands frame by frame. Use that diagnostic to explain native raster or memory anomalies; retain its exported recording separately from low-overhead timing runs. [WebKit Canvas debugging](https://webkit.org/blog/8452/canvas-debugging/).
- **Check whether a browser workaround is obsolete.** The widely cited Safari 17 `drawImage` privacy-protection regression was fixed in WebKit in January 2024. It does not establish the cause on an iPhone 17 Pro. Keep browser security settings intact and require a current reproducible profile before changing surface visibility or canvas architecture. [Resolved WebKit regression](https://bugs.webkit.org/show_bug.cgi?id=266181).

- **Recheck the owner after asynchronous preparation.** A completed network or storage request does not prove that the original menu intent is still valid. Retire late catalogue work before synchronous compilation or adoption; splitting it into helper functions alone does not create rendering opportunities. The new delayed-Missions reproduction makes this a required correction. [Long-task execution and yielding](https://web.dev/articles/optimize-long-tasks).
- **Distinguish asynchronous waiting from CPU attribution.** Web Crypto copies digest input and schedules the digest asynchronously. A loading label or long promise settlement is insufficient evidence that hashing caused the stall. Retain owner state, then correlate a separate CPU/frame diagnostic before moving work to a worker or changing validation. [Web Crypto digest algorithm](https://www.w3.org/TR/webcrypto/#SubtleCrypto-method-digest).

- **Use CPU samples for CPU questions and frame traces for browser rendering questions.** Chrome distinguishes sampled JavaScript stacks from layout/painting events and offers separate call-tree and bottom-up views. Join new HUD spans to a profiler only after proving their clock mapping. The current first-victory profile cannot explain a later Two Bays interruption, and sampled CPU alone cannot attribute GPU or compositor cost. Keep any such diagnostic separate from ordinary timing. [Chrome profiling reference](https://developer.chrome.com/docs/devtools/performance/reference).
- **Keep critical results immediate and defer only independent work.** The web.dev long-task example updates essential UI before yielding lower-priority work. Apply this only after attributing the current terminal HUD: required saves and authoritative state must retain their ownership/order. A microtask does not provide a rendering opportunity; yielding does not remove the work or prove its cost. [Long-task scheduling example](https://web.dev/articles/optimize-long-tasks).

Use available native entries as supplementary evidence without assuming the affected phone's browser version or replacing continuous-movement application measurements. Browser/device/version still belongs in physical qualification. [WebKit Safari 26.2](https://webkit.org/blog/17640/webkit-features-for-safari-26-2/).
- **Keep all CI partitions required.** GitHub matrix jobs can continue collecting evidence with `fail-fast: false`. [GitHub matrix behavior](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations).

The application markers are inclusive elapsed boundaries. Use the existing separate diagnostic to locate browser work before changing DOM order; batching reads/writes is a candidate only where actual ordering and cost support it. [WebKit timelines](https://webkit.org/web-inspector/timelines-tab/), [layout measurement guidance](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing).

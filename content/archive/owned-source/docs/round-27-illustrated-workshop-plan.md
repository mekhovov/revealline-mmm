`pack-source.json` is the baseline pack with version `1.1.0` and empty `levelVisuals`. The builder alone generates its embeddings. Use the common prompt plus the corresponding complete scene brief from the candidate; copy the full effective text into provenance for each generation. Preserve the `revealline-art-provenance.v1` convention demonstrated by [Homeward prompts](../authoring/library/homeward-skies/prompts.json): actual tool route, date, intended subject, asset ID, relative path, full prompt, original/parent reference, author and rights declaration, and observed review notes. Do not invent unavailable model metadata or mark review complete before inspection. Record dimensions, raw bytes and SHA-256 in the builder report and reviewed source handoff.

Generate with the available image-generation tool. Preserve each original PNG exactly as returned; copying bytes to its authoring path is allowed. Target a finished full-bleed **4:3** image, preferably 1536×1152, with coherent visible pixel clusters, crisp silhouettes, controlled light and a focal subject readable on a 280px-wide compact board. The tool's requested size is not its measured output. Require actual `width * 3 === height * 4`; inspect full resolution and actual downscaled play before accepting it. Homeward's actual 1448×1086 dimensions show why the prompt size must not become a false assertion.

Do not crop, resize, quantize, recolor, recompress or otherwise edit imagery using Python, Node, canvas exports or an image CLI. If a generated original exceeds budgets or misses the composition, preserve it under a separate source/attempt path and regenerate, or inspect it and request a separate derivative through the image-editing tool. Link any derivative to its exact parent, preserve both, and embed the selected file's exact bytes. Do not overwrite an accepted original silently. Hash/header/dimension reads and runtime `contain` drawing are validation/presentation, not image editing.

The candidate's reference rationale is retained: Petrykivka-inspired everyday objects and nature are supported by the [UNESCO tradition record](https://ich.unesco.org/en/RL/petrykivka-decorative-painting-as-a-phenomenon-of-the-ukrainian-ornamental-folk-art-00893?lang=en); memorable recognizable locations with their own twist follow [Gary Winnick's development account](https://blog.thimbleweedpark.com/location_location_location.html). Deliberate retro lighting is inspired by [Sabotage's own Sea of Stars description](https://sabotagestudio.com/presskits/sea-of-stars/), without claiming its renderer. The city is a fictional metaphor for coordination and spend visibility informed by [Coupa's platform account](https://www.coupa.com/blog/an-8-trillion-advantage-coupas-community-driven-ai-turns-transactions-into-intelligent-insights/). No reference artwork, branded mascot, screenshot or customer data is copied. These sources inform art direction, not measured enjoyment or historical certification.

## 3. Reproducible, bounded builder

Add a separate `scripts/build-workshop-pack.mjs`, modeled on the [Homeward builder](../scripts/build-homeward-pack.mjs). Do not refactor or regenerate Homeward for this increment. Export `buildWorkshopPack({root, write = false})` returning `{pack, report}`; allow only the CLI form `node scripts/build-workshop-pack.mjs [--write]`.

Before writing anything, validate the fixed source identity and three map bindings, compare the source's nonvisual content with the retained baseline, and read only the three designated regular, nonsymlink PNG files. Reject missing, empty, changed-during-read, non-PNG, oversized, duplicate-hash or non-4:3 sources. A distinct SHA is a byte-distinction check, not proof of distinct composition; visual review must also confirm three different scenes.

Emit exactly the current sidecar shape, with one entry per map:

```js
{
  levelId: 'workshop-01',
  visualOverrides: {
    background: {
      dataUrl: 'data:image/png;base64,...', // exact selected source bytes
      name: 'Garden of Threads',
      fit: 'contain',
      metadata: {
        title: 'Garden of Threads',
        description: 'A reviewed short description of this original scene.',
        author: 'Reveal Line · AI-assisted original artwork',
        license: 'Original project artwork',
        rightsStatus: 'Original AI-generated project illustration; source and effective prompt retained separately.'
      }
    }
  }
}
```

There is no `roles` wrapper. [Pack validation](../game/packs.mjs) checks every image scope and aggregate budgets; `preparePack` additionally awaits full image decode before adoption. The builder runs `inspectImageDataUrl` and `validatePack`, explicitly reporting **headers/structure checked; browser decode pending**. It does not pretend a header adapter decodes PNG pixels.

Default invocation checks that the existing generated pack matches source content and embedded bytes without writing anything; a missing or stale output is an actionable failure. `--write` replaces only `game/content/packs/equipment-workshop.json` after all checks. A rejected input must leave output and sources unchanged. Retain Homeward's parsed-content comparison convention so normal repository formatting does not require another artwork regeneration. Report actual output bytes/hash separately from canonical semantic equality.

Unchanged hard limits from [content.mjs](../game/content.mjs) and [packs.mjs](../game/packs.mjs): 4 MiB raw per image, 6 MiB encoded characters per image, 8192px per side, 16 million pixels per image, 20 MiB combined encoded characters and 32 million combined pixels, 24 MiB per pack and 48 MiB installed pack library. Aim for 1–3 MiB per PNG and a generated Workshop under 12 MiB; the target is stricter than the allowed contract and must be measured, not assumed. Reject or revise artwork rather than increase limits.

The [build allowlist](../game/build-config.json) copies the runtime pack; it does not copy these authoring originals. Thus the distribution should contain each Workshop picture only through its embedding, not another source PNG copy. Report actual six-pack installed bytes and final precache bytes/files against the existing 64 MiB/2000-file offline limit. No service-worker/cache-policy change is proposed.
